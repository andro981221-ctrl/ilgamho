# 일감호 수질개선 WTP 설문 — GitHub Pages + Google Sheets

정적인 웹사이트는 GitHub Pages에서, 응답 저장은 **Google Apps Script 웹 앱**을 통해 사용자가 소유한 Google Spreadsheet에서 처리합니다. GitHub에는 응답 데이터나 Google 계정 비밀번호를 저장하지 않습니다.

## 파일

- `index.html`: 설문 페이지, 가상 등록금 고지서 및 호수 전후 개념도
- `styles.css`: 모바일/데스크톱 반응형 스타일
- `app.js`: 필수 문항 검증, DBDC 4개 유형 무작위 배정, 자동 분기, 서버 전송
- `config.js`: Google Apps Script 웹 앱 URL 및 문의 이메일 설정
- `Code.gs`: 구글 스프레드시트에 응답을 저장하는 Apps Script 코드 (GitHub에는 올려도 되지만 시트에서 직접 붙여 넣어야 합니다)

## 1. Google 스프레드시트 생성

1. Google Drive에서 새 스프레드시트를 만듭니다. 예: `일감호_CVM_응답`
2. 메뉴 **확장 프로그램 → Apps Script**를 선택합니다.
3. 기본 `Code.gs` 내용을 전부 지우고 이 프로젝트의 `Code.gs` 내용을 붙여 넣습니다. 저장합니다.
4. 우측 상단 **배포 → 새 배포 → 유형 선택(웹 앱)**을 선택합니다.
5. **다음 사용자 인증 정보로 실행: 나(Me)**, **액세스 권한이 있는 사용자: 모든 사용자(Anyone)**로 지정하고 배포합니다. Google 권한 승인 화면이 표시될 수 있습니다.
6. 결과로 표시되는 `https://script.google.com/macros/s/.../exec` 주소를 복사합니다. 반드시 **`/exec`로 끝나는 배포 URL**을 사용합니다.
7. 스프레드시트에 `responses` 시트가 없으면 **첫 응답 때 자동 생성**됩니다. `received_at`, `response_id`, `bid1`, `bid2`, `answer1`, `answer2`, `response_pattern` 등 분석용 열을 자동 기록합니다.

> '모든 사용자'는 계정 없이 응답을 저장할 수 있도록 하기 위한 설정입니다. 데이터는 소유자 시트에만 기록되며, 설문 참가자가 시트 링크를 열람할 필요는 없습니다. 그러나 공개 쓰기 엔드포인트이므로 악의적 반복 호출을 완전히 방지하지 못합니다. 본조사 전에 충분히 점검하고 조사 종료 후 웹 앱 배포를 중단하세요.

## 2. GitHub 연결

1. `config.js`의 `scriptUrl`에 배포된 **Apps Script 웹 앱 URL**을 붙여 넣습니다. 연구 문의 이메일을 안내하려면 `contactEmail`에 입력합니다.
2. GitHub에 새 **Public Repository**를 생성합니다(예: `ilgam-survey`).
3. `index.html`, `styles.css`, `app.js`, `config.js`를 저장소 최상위에 업로드합니다. `Code.gs`와 `README.md`를 함께 올려도 됩니다.
4. **Settings → Pages → Build and deployment**에서 `Deploy from a branch`, `main`, `/ (root)`를 선택하고 저장합니다.
5. GitHub Pages에 나타나는 페이지 주소(일반적으로 `https://계정명.github.io/ilgam-survey/`)로 접속합니다.

## 3. 배포 전 필수 테스트

- **동의 '아니오'**, 대상 외 재학생 '아니오' 선택 시 아무 데이터도 제출되지 않고 종료되는지.
- B2 복수 선택이 저장되는지(`purpose_*` 열), B2 '방문 없음'이 다른 선택지와 동시에 선택되지 않는지.
- 가상 등록금 고지서와 C1에 **같은 최초 금액**이 표시되는지.
- C1의 예→2배, 아니오→절반으로 C1-1 또는 C1-2가 정확히 분기되는지.
- NN인 경우에만 C1-3·C1-4가 나타나는지.
- D/E 모든 필수 응답을 작성했을 때 실제 스프레드시트에 **한 행이 저장되고 완료 화면이 표시되는지**.
- 최종 테스트 행은 본조사 전에 시트에서 삭제하거나 `test` 별도 시트로 이동합니다.
- **실제 Google 계정/Apps Script 배포 환경에서 테스트해야 합니다.** 개발 환경에서 파일만 열어서는 서버 저장 완료를 확인할 수 없습니다.

## 분석용 변수

- 최초 제시 금액: `bid1`; 후속 제시 금액: `bid2`; 0/1 답변: `answer1`, `answer2`.
- 응답 패턴: `YY`, `YN`, `NY`, `NN` → `response_pattern`.
- 최초 제시금액은 페이지 최초 로드 시 네 유형 A/B/C/D 중 동일 확률로 배정되며, 같은 탭에서 새로고침하면 유형이 유지됩니다(`sessionStorage`). 무작위 배정은 **유형별 응답 수 균형을 보장하지는 않습니다**.
- B2는 `purpose_transit`, `purpose_walk`, `purpose_rest`, `purpose_scenery`, `purpose_event`, `purpose_never`, `purpose_other`의 0/1 열로 저장됩니다.
- 수질·경제·태도 항목은 숫자 코드로 저장됩니다. '잘 모르겠음' 등에 해당하는 마지막 코드는 **결측 처리 또는 별도 범주**로 취급하고 5점 평균에 섞지 않아야 합니다.
- 시나리오: 부담금 1회, 환경 상태 3년 유지(가상 조건).
- 변수 해석을 위한 설문 원문/코딩은 `index.html`, `app.js`를 참고하세요.

## 개인정보·윤리 유의

이 설문 자체는 성명·학번·이메일·접속 IP를 스프레드시트 열로 수집하지 않습니다. 다만 GitHub Pages/Google은 서비스 접속 과정에서 기술적 로그를 처리할 수 있으므로, 설문 안내의 개인정보 설명을 실제 운영 환경에 맞게 검토하세요. 응답에는 중복 제출 방지용 무작위 `response_id`가 기록되며 개인 식별정보는 포함하지 않습니다.

익명 응답은 제출 후 특정 응답을 식별해서 삭제하기 어려울 수 있습니다. 안내문에 연구 문의처를 기재하고, 수업 과제의 연구윤리·설문조사 기준을 확인하세요.

## 저장 확인에 관하여

브라우저에서 Apps Script로 직접 `fetch`하는 방식은 Google 리다이렉트/CORS 문제를 겪을 수 있습니다. 이 프로젝트는 **숨겨진 iframe으로 POST**하고, Apps Script 성공 페이지가 `postMessage`로 **저장 완료 확인**을 전달하도록 구현했습니다. Google의 웹 앱 iframe 실행 정책에 따라 성공 확인 메시지가 전달되지 않을 가능성이 있습니다. 이때 화면은 **저장 여부를 확인할 수 없다고 경고**하며, 성공을 거짓으로 표시하지 않습니다. 응답이 이미 저장된 경우 다시 보내더라도 같은 `response_id`를 이용해 중복 행을 방지합니다. 배포 후 실제 환경에서 반드시 테스트하세요.

운영 중 `권한이 필요합니다`, `저장 주소 미설정`, 또는 확인 실패가 발생한다면 Apps Script의 액세스 권한과 실행 기록, URL의 `/exec` 여부를 점검하세요. 스프레드시트 문서를 '모든 사용자에게 공개'로 공유할 필요는 없습니다.
